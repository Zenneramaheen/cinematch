# 🎬 CineMatch

A movie recommendation engine with a web UI — built with **Python, FastAPI,
pandas and scikit-learn**. Type a movie you love, get films that *feel* like it.

Runs **100% locally**: no API keys, no accounts, no external services.

![stack](https://img.shields.io/badge/Python-3.12-blue) ![tests](https://img.shields.io/badge/tests-28_passing-brightgreen)

## What it is

CineMatch is a **content-based recommender**. It ships with a bundled sample
dataset of 359 movies (Hollywood + Indian cinema) and suggests similar ones
using the text of their genres and plot overviews.

Features:

- 🔎 **Fuzzy search** with autocomplete — typos like "Inceptoin" still work
- 🎯 **"Because you watched"** recommendations with match scores
- 😌 **Mood picker** — `feel-good`, `mind-bending`, `dark`, `epic`, `sporty`…
- 🎲 **Surprise me** — a random highly-rated pick
- 🧊 **Cold-start safe** — unknown titles return *"did you mean…"* suggestions
  instead of errors

## How content-based filtering works (the 30-second version)

1. **Vectorize** — every movie becomes a list of numbers (a vector) using
   **TF-IDF** over its genres + plot overview. Movies described with similar
   words end up with similar vectors.
2. **Compare** — **cosine similarity** measures the angle between two vectors.
   Small angle = very similar movies.
3. **Rank** — for your movie, we sort every other movie by similarity and
   return the top-N.

Because we only use the *movies'* own attributes (not user behavior), the
system works for a brand-new user with zero history — that's why it's called
*content-based*.

## Quickstart

```bash
# 1. Create a virtual environment
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Run the server
uvicorn main:app --reload
```

Open **http://127.0.0.1:8000** 🎉 &nbsp;·&nbsp; API docs at
**http://127.0.0.1:8000/docs**

### Run the tests

```bash
python -m pytest tests/ -v
```

### Docker

```bash
docker build -t cinematch .
docker run -p 8000:8000 cinematch
```

## Example requests

```bash
# Movies similar to Inception
curl "http://127.0.0.1:8000/recommend?title=Inception&n=5"

# Typo? You get suggestions, not an error
curl "http://127.0.0.1:8000/recommend?title=Inceptoin"
# -> {"found": false, "suggestions": ["Inception", ...]}

# Top sci-fi, top-rated first
curl "http://127.0.0.1:8000/recommend?title=Dangal"   # (try: Moneyball, Rush…)

# Mood-based picks
curl "http://127.0.0.1:8000/mood/mind-bending?n=5"

# Fuzzy title search (powers the autocomplete)
curl "http://127.0.0.1:8000/search?q=godfather"

# All genres with counts
curl "http://127.0.0.1:8000/genres"

# Random highly-rated pick
curl "http://127.0.0.1:8000/surprise"
```

## About the dataset

`data/movies.csv` is **synthetic sample data**, generated by
`data/generate_movies.py`. Titles, years and genres refer to real, well-known
films, but the plot overviews are short original summaries written for this
project and the ratings are plausible placeholders — nothing was scraped.
Regenerate it any time with:

```bash
python data/generate_movies.py
```

To use real data, swap in the [MovieLens](https://grouplens.org/datasets/movielens/)
dataset — the engine only needs `title`, `genres` and `overview` columns.

## Key concepts to learn (interview prep)

- **TF-IDF (Term Frequency–Inverse Document Frequency)** — turns text into
  numbers. Words that appear often *in one movie* but rarely *across all
  movies* ("heist", "samurai") get high weight; common words ("man", "story")
  get low weight. That's how the engine knows what makes a movie distinctive.
- **Cosine similarity** — measures the angle between two vectors, ignoring
  their length. Two movies pointing in nearly the same direction = very
  similar, even if one plot summary is longer than the other.
- **Content-based vs collaborative filtering** — content-based recommends
  *similar items* ("you liked X, here's Y like X"); collaborative filtering
  recommends *what similar users liked* ("people who liked X also liked Z").
  Content-based needs no user data (no cold-start problem) but can't surprise
  you outside your taste bubble — that's the classic trade-off.
- **Why genres are weighted ×2** (`GENRE_WEIGHT` in `recommender.py`) — a
  shared genre is a stronger similarity signal than a shared ordinary word,
  so we repeat the genre tokens to boost their TF-IDF influence.
